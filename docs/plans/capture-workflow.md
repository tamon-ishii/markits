# 撮影フローの実装契約

| 操作 | 結果 |
| --- | --- |
| 「キャプチャ」を開く | ウィンドウ選択画面。カーソルを含めるチェックは初期状態でオフ。 |
| カーソルのチェックを切り替える | オプションのみ変更。ハイライト中の対象を選択しない。撮影・待機・ウィンドウ非表示を開始しない。 |
| チェックなしでウィンドウをクリック | クリック位置のウィンドウを即撮影し、編集画面へ。 |
| チェックありでウィンドウをクリック | そのウィンドウを対象に選択画面を閉じ、実際のキー名を表示した操作ポップアップで待機。 |
| 待機中にカーソルを動かし、表示されたキーを再度押す | その時点の画面・カーソル・位置・取得できた対象名を保存し、編集画面へ。 |
| 全画面撮影 | チェックなしなら即撮影。チェックありなら全画面を対象にキー待機。 |
| 範囲調整 | 撮影後の編集画面でクロップ。撮影画面には範囲ドラッグや追加の範囲決定を置かない。 |
| ホームから操作を記録 | ウィンドウを選択して開始。選択画面のカーソル設定を引き継ぐ。 |
| 編集画面から操作を記録 | 保存された撮影元ウィンドウで開始。単一の撮影元がない全画面画像は別途対象選択が必要。 |
| 記録中のカーソルチェック | 撮影オプションを変更。表示されたキーでホバーを保ったまま撮影。 |
| 再撮影 | 全操作・現在位置を表示し、待機上限を適用。カーソル付きのフレームでは保存位置へマウスを移動して撮影。 |
| ウィンドウ撮影のスナップ情報 | 撮影元のUI探索を開始し、画像内座標へ変換して画面と履歴に反映する。 |
| 保存・コピー・編集終了 | 未確定のクロップを適用してから実行する。 |
| 撮影失敗 | 操作ポップアップで理由を表示し再試行可能にする。明示的な取消以外で待機を終了しない。 |

選択処理の回帰確認は `npm run test:capture`、保存・再撮影・座標処理はデスクトップのRustテストで行う。
これらは実機でのホバー・画面切替の確認を代替しない。
