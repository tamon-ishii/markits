# Desktop localization

Markits Desktop supports Japanese (`ja`) and English (`en`). On Home, open
**Settings → Language / 言語**. The preference is stored locally and the Home
window reloads to apply it. Newly opened capture, recording, playback, and cursor
guide windows use the same preference. Without a saved preference, Japanese
system languages select Japanese; other system languages select English.

The CLI, image pixels, existing annotation text, target application names, and
external OS/library error details retain their original language.

## Adding UI text

- Import `t` from `apps/desktop/src/i18n.ts`.
- Wrap authored UI strings with `t('日本語の文言')`.
- For dynamic text, use a tagged template, e.g. `t\`対象：${windowName}\``.
  Translation runs before values are inserted, so user content is preserved.
- Add the English translation to `apps/desktop/src/locales/en.json`. Full
  messages can use numbered placeholders such as `{0}` and `{1}` to reorder
  values. Longer phrases take precedence over shorter labels.
- Japanese source text is the fallback. Do not pass user data, annotation text,
  or already interpolated third-party strings through `t`.
- Static app-owned HTML is translated once at startup. This is intentionally
  not a DOM observer and never scans subsequently loaded user content.
- Localize native desktop messages with `i18n::text(ja, en)` and formatted
  messages with `localized!(ja, en, arguments...)`. Keep interpolation values
  outside translated literals. `cmd_set_locale` initializes the backend before
  a webview starts its workflow.

Run `node --test tests/i18n.test.cjs` from `apps/desktop` for locale selection,
fallback, interpolation, and user-content preservation tests.
